# 2. Non-Functional Requirements (NFR) Specification — LegalEase

This document establishes the quality attributes, operational limits, security standards, and performance constraints governing the LegalEase system.

---

## 1. Performance & Responsiveness (NFR-P)
- **NFR-P1 (Generation Latency)**: For live Gemini generation, the 95th percentile response latency shall not exceed 5.0 seconds under standard broadband network conditions. In Demo Mode, generation latency shall not exceed 100 milliseconds.
- **NFR-P2 (Export Generation Speed)**: The system shall assemble and serialize DOCX, PDF, and TXT files within 500 milliseconds of user download request.
- **NFR-P3 (Frontend Responsiveness)**: The Streamlit UI must render input components and load presets instantly with zero noticeable interface freezing or UI unresponsiveness.

---

## 2. Security, Privacy & Secret Protection (NFR-S)
- **NFR-S1 (Zero Hardcoded Credentials)**: Under no circumstances shall API keys, secret tokens, or internal credentials be hardcoded in application source code. All secrets are managed via `.env` and loaded using `python-dotenv`.
- **NFR-S2 (Source Control Isolation)**: `.gitignore` must strictly exclude `.env`, `.env.local`, and any local secret configuration files from git tracking.
- **NFR-S3 (Client-Side Masking)**: API keys must never be exposed or returned in API responses, frontend JavaScript bundles, or browser DOM nodes.
- **NFR-S4 (Input Sanitization & XSS Mitigation)**: All user inputs must be processed through `sanitize_text()`, which strips executable HTML (`<script>`, `<iframe>`, `javascript:` handlers) and normalizes character sets while preserving legitimate legal punctuation.
- **NFR-S5 (Data Ephemerality)**: Legal documents generated by LegalEase are processed entirely in memory and session state. The server shall not persist sensitive contract data or party identities to persistent databases without explicit user consent.

---

## 3. Reliability & Fault Tolerance (NFR-R)
- **NFR-R1 (Zero-Crash Fallback / Demo Mode)**: If `GEMINI_API_KEY` is missing, expired, or invalid, the backend must not crash with an uncaught exception. It must automatically switch to deterministic Demo Mode and return `is_demo: True`.
- **NFR-R2 (Network Interruption Handling)**: If backend REST communication fails or times out, the frontend must execute an in-process direct generator fallback, ensuring user workflow continuity.
- **NFR-R3 (Graceful Error Messages)**: Error responses must provide human-understandable guidance (e.g. "Quota exceeded" or "Validation failure") rather than raw Python stack traces.

---

## 4. Usability & UI/UX Standards (NFR-U)
- **NFR-U1 (Professional Aesthetic)**: The interface must employ clean corporate design principles, featuring centered brand logos, balanced spacing, Georgia/Times New Roman legal typography, and dark-card preview containers.
- **NFR-U2 (One-Click Quick Testing)**: The interface must provide pre-configured sample scenario buttons (NDA, Freelance, Employment, Lease) to allow immediate evaluation without requiring manual typing.
- **NFR-U3 (Clarity of Legal Limitations)**: Prominent, high-visibility disclaimers must clearly advise users that outputs are draft templates and do not constitute certified attorney representation.

---

## 5. Portability & Maintainability (NFR-M)
- **NFR-M1 (Cross-Platform Compatibility)**: The platform must execute natively on Windows, macOS, and Linux without platform-specific binary dependencies.
- **NFR-M2 (Modular Separation of Concerns)**: Source code must adhere to strict modular boundaries:
  - Frontend (`app.py`)
  - Backend routing (`main.py`, `routes.py`)
  - AI engine (`ai_core/`)
  - Data contracts (`models/`)
  - Formatters and exporters (`document_utils/`)
  - Sanitization & config (`utils/`)
- **NFR-M3 (Testability)**: All core modules must be verifiable using automated unit and integration tests runnable via a single `pytest` command.
